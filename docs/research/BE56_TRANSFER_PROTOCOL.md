# BE-56 — reserved transfer protocol

Dated technical/research record; results and limitations apply to the versions described. Use [the README](../../README.md) for current status and planning.

13 October 2026. Two new fictional first-user tasks and the evaluation protocol are frozen in owner-only ignored storage. [Public manifest](../planning/be56-transfer-freeze.json) contains only IDs, hashes and provenance. No model has received either case and no outputs have been generated.

The author has seen both tasks. This is reserved transfer data, not blind external evaluation. The owner example/contact variants and all prior results remain development data. The full protocol is being frozen after that development work; its timing does not retroactively make any previous score held-out. No fixture names, fact strings or expected answers are copied into production checks.

Before transfer inference, choose a candidate that passes the development gate; freeze baseline/candidate installed digests, code/prompt/schema hashes, actual options, input bytes, sample order and scorer version. Generate each new task three times per model: six samples per model, no repair. Preserve errors, incomplete outputs and all raw stages. Same seed/temperature repetitions do not estimate independent variance. Assess structure/effort, source/freshness, authority, changed facts, actionable checks/drafts, pivotal unknown/alternatives and owner readability separately. All six must validate; no critical factual/authority error; at least four complete-usefulness passes, including at least two per task. Analyst scoring and owner acceptance are separate.

The independent-proposal protocol reserves five meetings per model, canonical CSO/CFO/CEO and seed 47. First proposals get only owner sources/current facts; critique gets attributed proposals, with actual objections and no forced disagreement. Require two distinct proposals or an explicit reason no alternative; punctuation/case normalization must not imply voting. Candidate prompts/role bindings/schema/assets must freeze before those runs. The current helper does not implement the round, so no independence or diversity result is claimed.

If a transfer failure is used for a repair, preserve its score and promote the task to development. Reserve a fresh unused task for the next final assessment. Do not tune against transfer outputs, hide retries or mark work Done from analyst scores. Short-request/full-team owner review through normal startup remains required.

State: protocol and input freeze ready for review; candidate-specific freeze, inference, independent rounds and owner assessment pending. No model download, board write, merge, or rollout authority follows.
