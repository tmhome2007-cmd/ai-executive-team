# Sprint 5 — exactly where to go and what to enter

Run `./company review` to show this guide again. It does not load your key or change data.
Run `./company review --demo` for the fictional four-case recovery screen: the command
prints its exact URL and demo key after building. Open that URL, paste that demo key,
click Confirm, then choose Business research > Run inspector. Run #1 can continue;
#2 deliberately reports a changed model; #3 deliberately reports an unavailable
model; #4 has unknown historical identity and no Continue button. Keep its terminal
open; Ctrl+C stops only the demo. It uses temporary data and synthetic inference.
Run `./company review --check` for the complete automated fictional work scenario.
Test assessments are simulated, never your actual usefulness acceptance.

To review your own existing configured company: run `./company start`, open
http://127.0.0.1:3000 and paste the existing key copied by the launcher. If you need
it again, `./company key` copies it without showing or replacing it. The Sprint 5
checkout does not have a copied company key/database; the demo works independently.
Do not generate a new key, copy a database or overwrite .env just to follow this guide.

## Useful-work walkthrough (fictional data to enter)

1. Open Business research > Research & practice. If navigation is collapsed, open
   the menu at the top left. Select at least three existing dated fictional source
   records. Do not fetch real websites or treat platform facts as buyer demand.
   If you have no suitable records, use the disposable `--check` scenario instead.
2. Research title: `Fictional task app — private clarity exercise`.
   Constraints: `Private text only. No tools, publishing, customer contact, spending or generated code execution.`
   Click Save research brief, then Go to next step to compare options locally.
3. When the next-step card asks you to choose private practice, click Go to next step.
   Choose the existing Beginner task guide preset. It fills the exact existing
   supplied facts and rubric; keep them unchanged. Select a future review time
   using the date control, then click Approve this practice plan only.
4. Click Go to next step to generate the private draft. Local model identity must
   resolve; failed or unavailable generation stays blocked. No cloud fallback occurs.
5. Click Go to next step to open Full sample. Read it before choosing Passed or
   Failed for each check. In What you checked and observed, state what the sample
   actually does. Example only, if observed: `The same task moves from Read chapter
   one to Read chapter two and then completion. Controls and reminders are labelled
   unknown. Three FAQ answers are present. No testing or approval is claimed.`
   Do not copy this as evidence unless it matches the displayed sample.
6. If a check fails, record that result and concrete feedback. Example only if true:
   `The guide invents a Save button that was not supplied. Remove it and keep the
   interface controls explicitly unknown.` Click Record practice review, then
   Go to next step to revise. Assess the revised sample afresh under the same checks.
7. In Private deliverable files, choose the original sample, TXT, then Export saved sample.
   Repeat with the revised sample (TXT or Markdown). Choose those two files in
   Original artifact and Revised artifact, then Compare files. Export preserves
   the saved text; comparison alone does not establish improvement.
8. For procedure reuse, Executive skills requires two different exercises with the
   same rubric and latest passing assessments. Propose and review a procedure;
   only after its explicit acceptance can you select it for a new private exercise.
   Its new sample still needs assessment. The automated scenario proves this gate
   without pretending that you accepted any real work.
