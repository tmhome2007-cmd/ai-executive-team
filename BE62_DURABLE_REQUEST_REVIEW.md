The dashboard records a random request reference before submission. A reload keeps that reference, without adding the request body or API key to its recovery storage. Check Request Status distinguishes queued/running, saved, failed and interrupted work. History refresh never starts another meeting. Close Recovery refuses running work; an unstarted request receives a durable closure marker so late delivery cannot start it. No cancellation or automatic replay is claimed.

The API atomically binds the reference to an input hash. Repeating the same in-progress identity returns its state; changed inputs conflict. A completed repeat returns the saved response and original contributions with HTTP 200, preserving existing clients without rerunning the model or notification. Failed/interrupted work requires a new explicit request. Startup reconciliation uses the existing exclusive database-instance lock, recovers already-saved results and marks only unsaved old work interrupted. Local request rows contain hashes/status/references, not another copy of private input text.

Source review versions and freshness are frozen together and checked inside the decision insertion transaction. A source review change or expiry during generation blocks insertion and requires review again. Current intake answers are bound to the owner's browser timezone/review day and rechecked at insertion; a later day cannot silently reuse “works today”. Confirmation is still input review, never action approval.
